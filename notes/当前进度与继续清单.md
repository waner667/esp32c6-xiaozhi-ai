## 二、⚠️ 最重要的架构教训（下次一定再用得上）

`Application::Initialize()` 会把 `board.GetDisplay()` **缓存成局部指针**，然后调 `SetupUI()` / `SetChatMessage()`。

**运行期把 `display_` 从 NoDisplay 换成真屏 = UI 全丢。** 症状极具迷惑性：屏会闪一下（驱动 init 刷了一帧 RAM），然后一直黑 —— 看起来像屏坏了，其实是没人再往里画东西。

**正确做法**：任何需要延迟/异步初始化的外设（屏、codec 芯片）都用**代理对象**，不换指针。

已在 `compact_c6_board.cc` 落地 `DeferredDisplay`：
- 缓存 `last_status_` / `last_emotion_` / `last_chat_role_` / `last_chat_content_`
- `Attach(Display* real)` 接上真屏时按序重放：SetupUI → SetStatus → SetEmotion → SetChatMessage
- `display_` **整个生命周期只赋值一次**，永远指向 DeferredDisplay
- 屏什么时候醒都能正确显示 UI，且开机不被拖慢

## 三、OLED 排查全过程（已解决，记录以免重走）

### 根因：SSD1306 charge pump 上电极慢
| 探测时机 | 结果 |
|---|---|
| 启动 150ms | 全 miss |
| 延时 600ms | 全 miss |
| 延时 2500ms | 仍全 miss |
| 运行几秒后（后台任务） | `0x3C @ 100k/400k` **稳定 HIT**，连续多轮 |

最终方案：**启动不等屏**。等 500ms 快速探一次（每组合 2 次），探不到就起后台任务每 2 秒重试，命中即 Attach。开机不卡，UI 由代理自动补齐。

### 误判记录（都排除了，别再怀疑）
| 曾经的误判 | 实际情况 |
|---|---|
| SDA/SCK 接反了 | ❌ 接线从头到尾是对的（当前 SDA=11 / SCK=10） |
| OLED VCC 虚焊 | ❌ 万用表量到 2.67V 属正常，屏能应答就是好的 |
| 地址是 0x3D 不是 0x3C | ❌ 真实地址是 **0x3C**，0x3D@50k 的"命中"是 ESD 钳位假象 |

### 沿途修掉的两个真 bug
1. **`esp_lcd_panel_io_tx_param(panel_io_, 0xAE, NULL, 0)` 触发 abort**
   IDF 6.1 的 i2c master 内部有 `ESP_ASSERT` 拦截空数据指针 → `abort()`（MCAUSE 0x2）。已改为传单字节缓冲 / 跳过该步。
2. **50kHz 会让设备卡死**
   IDF 6.1 的 i2c master 在 50kHz 下日志断在探测中途，无任何后续输出（实测两次）。**速率只用 400k / 100k。**

### 万用表量测口诀（waner 常混淆）
- 断电 → 拨 **Ω 电阻档**量 SDA/SCK 对 GND：`∞`/`OL` 或几 kΩ 都正常，**读 0 才是短路**
- 上电 → 拨 **V⎓ 直流档**量电平：`3.0~3.4V` 正常，**读 0V 才是问题**
- **断电量电压永远是 0V，无意义**
- 读到什么 `0.6V` 左右 →是 **ESD 保护二极管钳位**，说明屏侧 VCC 没接通

## 四、抓串口日志的三个坑（照做，别试错）

CH343 芯片有个老毛病：**收到复位脉冲后必断流**，只能抓到前 700ms 左右。

1. **`Select-String` 挂在 PowerShell 管道里抓不到 Python 原生 stdout** → 必须让脚本落盘，再用正则筛文件
2. **反复调`reset_and_capture.ps1` 会让 CH343 来不及重新枚举** → 可靠做法：
   - 一次开端口多轮：`repeat_reset.py`
   - 或**烧录后立即监听**（esptool 结尾会硬复位，CH343 不重新枚举）：`flash_c6.ps1` 后接`listen_only.py`
   - 或复位后 `Start-Sleep 2` 再开端口
3. **判编译成功看 `BUILD_EXIT=0` + `Successfully created ESP32-C6 image.`**，退出码可能因管道提前关闭而假失败

如果代码里有**周期性重试打印**（如本例的 OLED WATCH），纯 `listen_only.py` 就能抓到，不依赖启动窗口 —— 排查异步初始化问题时应优先用这招。

## 八、IDF 6.1 的三个坑

1. **50kHz I2C 会让设备卡死**（日志断在探测中途）。速率只用 400k / 100k。
2. **`i2c_del_master_bus` 不能用来切引脚方向**。内部 `i2c_master_bus_destroy` 执行 `free(handle); handle = NULL;` —— 只置空**自己的局部副本**，调用方指针变悬垂，紧接着 `i2c_new_master_bus` 就 `Load access fault`。IDF 6.1 没有公开的 bus_destroy API，也没有 GPIO swap API，**运行时切 SDA/SCL 不可行，要换接法只能改 `config.h` 重编译**。
3. **`esp_crt_bundle` 在 IDF 6.1 有越界 bug**（`get16_le` 访问越界）。用 IDF v5.4 的 fork（如 TF1990）不受影响。

## 九、esptool 5.x 语法坑

```powershell
# 正确：--baud 是全局选项必须在 write-flash 之前；--flash-* 是子命令选项
esptool --chip esp32c6 --port COM10 --baud 460800 write-flash `
        --flash-mode dio --flash-size 16MB --flash-freq 80m `
        0x0 bootloader.bin 0x8000 partition-table.bin ...
```
- `--baud` 写成子命令选项 → `No such option '--baud'`
- `--flash-mode` 写成全局选项 → `No such option '--flash-mode'`
- `chip_id` 已废弃 → 用 `chip-id`
- PlatformIO 自带的 `tool-esptool/esptool.exe` 是 2014 年的 esptool-ck v0.4.13（**不支持 C6**），必须用 pip 装的新版

### 写 PowerShell 脚本的两个坑
1. **脚本内容一律用纯 ASCII** —— 含中文时经工具写盘会出现引号被破坏 → `字符串缺少终止符` 解析错误
2. **`$ErrorActionPreference='Stop'` 会把 native 进程的 stderr 提升为终止性错误**，且 `2>$null` **无效**。正确写法：临时改 `Continue` → 取 `$LASTEXITCODE` → 恢复 → 用 `Where-Object { $_ -isnot [System.Management.Automation.ErrorRecord] }` 滤掉 stderr
